# ADR 0004 — HLS 720p privado en fMP4

- **Estado**: aceptada (implementación parcial)
- **Fecha**: 2026-11

## Contexto

Los videos deben verse sin descargar el original completo, pero el bucket es privado y las URLs firmadas caducan. Un `video/mp4` de 1 GB no es una experiencia aceptable y el free tier de B2 no permite servirlo muchas veces. Tampoco queremos un servidor de streaming.

## Decisión

- Transcodificar a **HLS VOD 720p**:
  - H.264 High, `yuv420p`, CRF 23, preset `veryfast`;
  - audio AAC 128 kbps;
  - segmentos **fMP4 de 4 s** (`init.mp4` + `seg_XXXX.m4s`);
  - playlist `master.m3u8` en `vaults/<vault>/<asset>/hls/`.
- Guardar el original. La opción de borrarlo (“liberar original”) queda para más adelante, porque la papelera y una futura descarga completa lo necesitan.
- El worker sube todos los segmentos y registra un derivado `hls` con la key del master.
- La reproducción futura usará un endpoint propio que:
  1. valide la sesión/rol,
  2. lea el master y las playlists,
  3. reescriba cada URI relativa como URL firmada por segmento.

## Por qué no otras opciones

| Opción | Motivo |
| --- | --- |
| MP4 progresivo | Descarga total o seeking costoso; malo para 1 GB |
| Transcodificar a muchas calidades | CPU y almacenamiento x N; 720p es suficiente para un archivo personal |
| Servicio de video (Mux, Cloudflare Stream) | Coste y dependencia; no hay free tier real |
| HLS con segmentos públicos | Rompe la privacidad |

## Consecuencias

- El player necesita `hls.js` en navegadores sin HLS nativo (Chrome/Firefox).
- Las playlists firmadas se pueden cachear poco o nada; cada firma de segmento dura ~1 h.
- Los segmentos no se registran individualmente en la base de datos: se comparten prefijo y se limpian con el asset.
- El estado actual reproduce el original en el `<video>` como puente; el endpoint de playlist firmada es la siguiente tarea.
